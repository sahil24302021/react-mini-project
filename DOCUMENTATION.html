1. Project Overview — What Palette Studio Does

Palette Studio is a professional-grade color generation and exploration tool built as a single-page React application. It helps designers and developers instantly generate beautiful, harmonious color palettes based on established color theory.

Core Features

🎨 Color Generation

One-click random color generation with harmonic palette (complementary, analogous, triadic, split). Press Space or ⌘+G to generate.

📋 Multi-Format Copy

Copy any color in HEX, RGB, or HSL format with a single click. Visual feedback via toast notifications.

🌈 Gradient Generator

Create linear, radial, or conic gradients from your generated palette. Adjustable angle with live preview.

💾 Save & Export

Bookmark colors to your collection (persisted in localStorage). Export as CSS, SCSS, Tailwind, JSON, SwiftUI, or Compose.

🔍 Explore by Mood

Browse 80+ curated colors organized by mood (Vermillion, Ember, Cerulean, etc.) and tone (Vivid, Muted, Pastel, Deep).

♿ Accessibility Checker

WCAG contrast ratio display, AA/AAA pass/fail badges, and color vision deficiency simulation (protanopia, deuteranopia, tritanopia).

How a User Interacts with It

The typical user flow is:

  1. Generate — Press Space bar or click "Generate" to create a random color
  2. Explore — View the 4 harmonic swatches generated automatically
  3. Copy — Click any color/format chip to copy to clipboard
  4. Save — Bookmark favorites to your collection
  5. Export — Download the entire palette as CSS, JSON, or other formats
  6. Create Gradients — Mix palette colors into beautiful gradient CSS

4. How the Application Boots (Entry Point Flow)

When a user opens Palette Studio, here is exactly what happens, step by step:

Step 1: index.html Loads

The browser loads index.html, which does three things:

  • Sets up SEO meta tags (title, description, Open Graph)
  • Loads three Google Fonts: Playfair Display (headings), JetBrains Mono (code/labels), DM Sans (body text)
  • Creates a <div id="root"> and loads src/main.tsx as an ES module

Step 2: main.tsx Creates the React Root

// main.tsx — The very first React code that runs
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App'
import './index.css'  // ← This loads ALL global styles

ReactDOM.createRoot(document.getElementById('root')!)
  .render(
    <React.StrictMode>  // ← Enables extra development checks
      <App />
    </React.StrictMode>
  )

Step 3: App.tsx Sets Up Routing & Context

export default function App() {
  return (
    <BrowserRouter>           // ← Enables URL-based navigation
      <ColorProvider>          // ← Makes color state available EVERYWHERE
        <Routes>
          <Route path="/"        element={<HomePage />}    />
          <Route path="/explore" element={<ExplorePage />} />
          <Route path="/saved"   element={<SavedPage />}   />
          <Route path="/docs"    element={<DocsPage />}    />
          <Route path="*"        element={<NotFoundPage />}/>
        </Routes>
      </ColorProvider>
    </BrowserRouter>
  )
}
Why ColorProvider wraps everything: By placing <ColorProvider> outside the <Routes>, the color state persists when navigating between pages. If you generate a color on the home page, it's still active when you visit the Saved page.

Step 4: Each Page Uses PageLayout

Every page wraps its content in <PageLayout>, which provides the consistent shell:

┌─────────────────────────────────────┐ │ Navbar │ ← Fixed, scrolls to pill shape ├─────────────────────────────────────┤ │ │ │ {children} │ ← Page-specific content │ (Hero, Palette, etc.) │ │ │ ├─────────────────────────────────────┤ │ Footer │ ← Links, brand, glow line ├─────────────────────────────────────┤ │ Toast │ ← Floating notification popup └─────────────────────────────────────┘

5. State Management — The ColorContext System

Palette Studio uses React's Context API as its state management solution. This is like a global store that any component can read from or write to, without passing props through every level.

What Data is Stored

StateTypePurpose
colorGeneratedColorThe currently active color with all its derived data (hex, rgb, hsl, mood, palette, contrast)
historyGeneratedColor[]Last 12 generated colors (newest first)
savedGeneratedColor[]User's bookmarked collection (max 24, saved to localStorage)
isGeneratingbooleanPrevents double-clicks during the 160ms generation delay
copiedstring | nullThe text currently in clipboard (for showing ✓ feedback)
toastToastData | nullActive toast notification message

How Actions Work

generate() — Creating a New Color

const generate = useCallback(() => {
  if (isGenerating) return  // ← Debounce: prevent rapid-fire
  setGenerating(true)
  setTimeout(() => {        // ← 160ms delay for smooth feel
    const next = buildGeneratedColor(generateRandomHex())
    setColorState(next)                      // Update current color
    setHistory(prev => [next, ...prev].slice(0, 12))  // Add to history (cap at 12)
    setGenerating(false)
  }, 160)
}, [isGenerating])

Why the 160ms delay? Without it, color changes feel instantaneous and jarring. The short delay gives Framer Motion time to animate the color transition smoothly, creating a premium "processing" feel.

copyText() — Clipboard with Fallback

const copyText = async (text: string) => {
  try {
    await navigator.clipboard.writeText(text)  // Modern API (requires HTTPS)
  } catch {
    // Fallback for HTTP or older browsers:
    // Create invisible textarea, copy via execCommand, then remove
    const el = document.createElement('textarea')
    el.value = text
    document.body.appendChild(el)
    el.select()
    document.execCommand('copy')
    document.body.removeChild(el)
  }
  setCopied(text)           // Show ✓ icon on the copied element
  showToast(`Copied ${text}`) // Show bottom toast notification
  // Auto-clear after 2 seconds
  timerRef.current = setTimeout(() => setCopied(null), 2000)
}

Keyboard Shortcuts

// Registered in useEffect — listens for keydown globally
const onKey = (e: KeyboardEvent) => {
  // Don't trigger if user is typing in an input field
  if (tag === 'INPUT' || tag === 'TEXTAREA') return
  // Space bar OR Ctrl/Cmd+G → generate new color
  if (e.code === 'Space' || (e.metaKey && e.key === 'g')) {
    e.preventDefault()  // ← Prevent page scroll on Space
    generate()
  }
}

6. Color Science — The Core Algorithm Library

The file utils/colorUtils.ts contains ALL the color mathematics. It has zero dependencies — everything is pure math. Here's how each algorithm works:

6.1 Color Space Conversions

Colors can be represented in multiple formats. The app converts between them freely:

HEX (#FF6B35) ↕ hexToRgb() / rgbToHex() RGB (255, 107, 53) ↕ rgbToHsl() / hslToHex() HSL (20°, 100%, 60%)

hexToRgb() splits the 6-character hex string into 3 pairs and converts each from base-16 to base-10:
"FF" → parseInt("FF", 16) → 255

rgbToHsl() uses the standard algorithm: normalize RGB to [0,1], find max/min channels, compute lightness as their average, saturation based on the delta, and hue based on which channel dominates.

6.2 Mood Classification System

Every color gets a poetic mood name based on its position on the HSL color wheel:

Hue RangeMood NameColor Family
0° – 15° / 345° – 360°VermillionPure reds
15° – 30°EmberOrange-reds
30° – 50°AureateGolds & ambers
50° – 70°CitrineYellows
70° – 100°VerdantYellow-greens
100° – 150°MalachiteGreens
150° – 185°GlacialTeals
185° – 220°CeruleanBlues
220° – 255°CobaltDeep blues
255° – 285°AmethystPurples
285° – 315°MauvePink-purples
315° – 345°CarmineHot pinks

Special cases: Lightness < 8% → "Void" (near-black), Lightness > 93% → "Celestial" (near-white), Saturation < 8% → "Obsidian" or "Lunar" (grays).

6.3 Harmonic Palette Generation

This is the heart of the color theory engine. From any base color, it generates 4 harmonics using hue rotation on the color wheel:

0° (base) │ 330° ───────┼─────── 30° (Analogous +30°) / │ \ / │ \ / │ \ 270° │ 90° \ │ / \ │ / \ │ / 210° ───────┼─────── 150° (Split +210°) │ (Triadic +120°) │ 180° (Complementary)

Each harmony also adjusts saturation (ds) and lightness (dl) slightly for more natural-looking results. Values are clamped to safe ranges (S: 15-95%, L: 12-88%) to prevent washed-out or too-dark outputs.

6.4 WCAG Contrast Calculation

The app calculates the relative luminance using the W3C formula and computes contrast ratios against both white and black backgrounds. The higher ratio is displayed along with AA (≥4.5:1) and AAA (≥7.0:1) compliance badges.

7. Component Architecture — UI Building Blocks

Components follow the atomic design methodology: small reusable atoms → composed into larger organisms → assembled into pages.

7.1 Button Component (ui/Button.tsx)

A versatile animated button with 3 variants and 3 sizes:

VariantStyleUse Case
primarySolid white background, dark text, glow shadowMain CTAs (Generate, Start)
ghostTransparent, subtle hover highlightSecondary actions (Explore link)
outlineBorder only, transparent fillTertiary actions (Save, Export)

The animation magic: Uses Framer Motion's whileHover (scale 1.025, lift -2px) and whileTap (scale 0.96) with spring physics (stiffness: 500, damping: 25) for a natural, bouncy feel. The primary variant also has a gloss overlay that appears on hover via CSS gradient.

7.2 Icons System (ui/Icons.tsx)

Instead of importing a heavy icon library, the project uses a custom SVG icon factory:

// Factory function: creates an icon component from an SVG path string
const ico = (d: string) => ({ size, className }) => (
  <svg width={size} height={size} viewBox="0 0 24 24" fill="none">
    <path d={d} stroke="currentColor" strokeWidth="1.6" />
  </svg>
)

// Usage: each icon is just a path string passed to the factory
export const CopyIcon = ico('M9 9h13v13H9zM5 15H4a2...')

This approach keeps the bundle tiny (2KB for 13 icons vs ~50KB+ for a full icon library). Each icon uses stroke="currentColor" so it inherits its color from the parent's CSS color property.

7.3 Toast Component (ui/Toast.tsx)

A floating notification that appears at the bottom-center of the screen when colors are copied or saved:

  • Entry animation: slides up from 30px below, scales from 0.95 to 1
  • Exit animation: fades out while sliding down 20px
  • Auto-dismiss: disappears after 3 seconds (timer managed in ColorContext)
  • Style: glassmorphic (blur + semi-transparent) with a gold check icon

7.4 Navbar Component (layout/Navbar.tsx)

The most animation-heavy layout component. Key behaviors:

Scroll-Responsive Pill: When scrollY > 20px, the navbar smoothly transitions from a full-width transparent bar to a floating 800px-wide pill with glassmorphic blur, rounded corners, and an inner shadow. This is achieved via inline Framer Motion styles that interpolate based on the scrolled state.

Active Route Indicator: Uses Framer Motion's layoutId="nav-underline" — when the active page changes, the golden underline dot smoothly slides to the new link position using shared layout animations (spring: stiffness 380, damping 30).

Mobile Menu: A hamburger icon (3 lines) animates to an X when clicked. Each line uses independent rotation transforms. The full-screen overlay uses staggered entry (0.06s delay between items) with a lifted easing curve.

9. Animation System — How Every Motion Works

Palette Studio uses Framer Motion extensively. Here's a breakdown of every animation technique:

9.1 Spring Physics

Instead of CSS easing curves (ease-in, ease-out), most animations use spring physics with two parameters:

ParameterWhat It ControlsTypical Value
stiffnessHow snappy/fast the spring responds350–500 (high = snappy)
dampingHow quickly oscillations settle25–40 (high = less bounce)

Example: Button hover uses stiffness: 500, damping: 25 for a quick, subtly bouncy lift.

9.2 The 3D Tilt Card (HeroSection)

This is the most complex animation in the app. Here's how it works step by step:

// 1. Create motion values that track mouse position (0 to 1)
const x = useMotionValue(0.5)  // 0.5 = center
const y = useMotionValue(0.5)

// 2. Apply spring smoothing so movement isn't jittery
const mouseXSpring = useSpring(x, { stiffness: 400, damping: 40 })

// 3. Map mouse position to rotation angles
const rotateX = useTransform(mouseYSpring, [0, 1], ["5deg", "-5deg"])
const rotateY = useTransform(mouseXSpring, [0, 1], ["-5deg", "5deg"])

// 4. In onMouseMove, calculate normalized position
x.set(mouseX / rect.width)   // 0 at left edge, 1 at right
y.set(mouseY / rect.height)  // 0 at top, 1 at bottom

// 5. On mouse leave, spring back to center
x.set(0.5); y.set(0.5)  // ← This triggers a spring animation back

The result: the card tilts toward the cursor (max ±5°), with a radial gradient "glare" that follows the mouse position, creating a realistic 3D reflection effect.

9.3 Staggered List Animations

The palette swatches use Framer Motion's variant orchestration pattern:

// Parent container variant — staggers children by 0.08s
const container = {
  hidden: {},
  show: { transition: { staggerChildren: 0.08 } }
}

// Each child starts 24px below, scaled to 93%, then springs in
const item = {
  hidden: { opacity: 0, y: 18, scale: 0.93 },
  show: { opacity: 1, y: 0, scale: 1,
           transition: { ease: [0.16, 1, 0.3, 1], duration: 0.55 } }
}

9.4 Layout Animations

Navbar underline: Uses layoutId="nav-underline" — shared layout animations automatically interpolate position and size when the active route changes.

History strip: AnimatePresence mode="popLayout" smoothly manages entry/exit of color swatches as new ones are generated.

11. Accessibility & WCAG Compliance

11.1 Contrast Ratio Checker

Every generated color displays its WCAG contrast ratio directly on the 3D card. The calculation follows the W3C spec:

// Step 1: Linearize sRGB values (remove gamma)
const linearize = (c) =>
  c <= 0.03928
    ? c / 12.92
    : Math.pow((c + 0.055) / 1.055, 2.4)

// Step 2: Calculate relative luminance
L = 0.2126 * R + 0.7152 * G + 0.0722 * B

// Step 3: Contrast ratio = (lighter + 0.05) / (darker + 0.05)
// Tested against both white (#FFF) and black (#000)
// The HIGHER ratio is displayed

The badge shows green for AA-passing ratios (≥4.5:1) and red for failing ones.

11.2 Color Vision Deficiency (CVD) Simulation

The palette section includes a toggle to simulate three types of color blindness:

TypeAffectsPrevalenceWhat Changes
ProtanopiaRed cones~1.3% malesReds appear darker/brown, can't distinguish red from green
DeuteranopiaGreen cones~1.2% malesGreens appear beige/yellow, similar red-green confusion
TritanopiaBlue cones~0.01% allBlues appear green, yellows appear pink/light

The simulation uses transformation matrices (Brettel, Viénot & Mollon 1997) that remap RGB channels based on how the affected photoreceptors process light. This helps designers ensure their palettes are distinguishable for all users.

11.3 Other Accessibility Measures

  • Keyboard navigation: Space and ⌘+G shortcuts for color generation (disabled when typing in inputs)
  • Clipboard fallback: Uses execCommand('copy') when the modern Clipboard API isn't available
  • Semantic HTML: Proper <section>, <nav>, <main>, <footer> landmarks
  • Aria labels: Mobile menu button has aria-label="Menu"
  • Dynamic text colors: Text on color blocks automatically switches between dark and light based on the isLight calculation

12.5 Key Design Decisions Explained

DecisionReasoning
Context API over ReduxThe state is simple (one color + lists). Redux would add unnecessary complexity and boilerplate for this scope.
Tailwind + CSS Variables hybridTailwind for rapid layout; CSS variables for dynamic theming (colors change at runtime, not build time).
Pure math, no color libraryKeeps the bundle small. Color conversion math is well-documented and stable — no need for a dependency.
Custom SVG icons13 icons at 2KB vs. installing react-icons (100KB+). Path strings are tiny and tree-shaking is guaranteed.
localStorage persistenceNo backend needed. Saved colors survive page refreshes. Simple, privacy-friendly, and free.
HSL for random generationRandom RGB produces muddy colors. HSL with constrained S/L ranges guarantees vivid, usable results.
